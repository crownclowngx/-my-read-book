# 第二章（3/6）：参数越多越好吗——规模、算力与成本

模型的名字越来越复杂，参数数字也越来越大。最容易形成的直觉是：预算允许，就选择最大的那个。

《AI工程》第二章让我停下来区分三个问题：模型有多大，训练投入了多少计算，以及完成我的任务究竟要花多少钱。这三件事有关，却不能相互替代。

> 本篇对应原书2.2.2“模型规模”。公式仅用于说明量纲与估算边界，示例不是某个商用服务的报价。补充资料查阅于2026年10月15日。

**阅读导航：** 本系列第3篇。前两篇讨论数据与架构，后续讨论后训练、采样与可靠输出。

**本章六篇：** ①训练数据 → ②模型架构 → ③规模与成本 → ④后训练 → ⑤采样与推理 → ⑥可靠输出。

## 1. 先把三个单位分清楚

参数是训练时被学习的数值；token是处理序列的单位；FLOPs是浮点运算次数。FLOP/s则表示每秒能够完成多少浮点运算，属于速率。

因此，训练计算量除以有效计算速率，才可能估计训练时间。不能把一个总运算量与“每秒算力”放在一起比较大小，却忽略时间单位。

| 量 | 它描述什么 | 不能直接说明什么 |
| --- | --- | --- |
| 参数量N | 模型中可学习数值的规模 | 目标任务的准确率 |
| 训练token数D | 训练处理的数据量 | 数据质量与独立信息量 |
| 计算量C | 训练消耗的运算 | 实际训练花费与总研发成本 |
| FLOP/s | 计算吞吐速率 | 真实负载下始终达到的性能 |

一个常见的稠密Transformer训练粗估是C≈6ND。它省略了许多架构和训练细节，不适合直接套到所有MoE、多模态和超长上下文训练上。我的用法是拿它检查数量级，而不是拿它生成采购预算。

例如，N=10亿、D=200亿时，粗估计算量为1.2×10²⁰ FLOPs。这个结果还没有告诉我们机器利用率、通信、失败重跑和设备单价。

## 2. 规模定律回答的是资源怎样分配

在一定模型族、数据及训练设置下，研究者观察到损失与参数、数据、计算投入之间存在可以拟合的规律。它使团队能够根据较小实验，对更大训练的结果进行估算。

这里的损失，可以初步理解为模型在预测训练目标时的误差度量。损失下降可能支持能力改进，但不是每一项业务指标都会按同样比例变化。

Chinchilla研究的关键启发是：固定训练计算预算时，不应只扩大参数而让数据投入失衡；参数与训练token需要共同考虑。具体比例来自研究条件，不是一条适用于所有模型的永恒配方。[Chinchilla论文](https://arxiv.org/abs/2203.15556)

```text
训练预算 → 参数规模、数据质量与数量、架构、有效算力
                           ↓
                  得到一个候选模型
                           ↓
应用预算 → 质量、延迟、并发、上下文、缓存、运行与审核
                           ↓
        固定任务与条件，比较“成功完成一次”的总成本
```

*图4（文字流程）：训练最优与应用最优涉及不同约束，箭头表示决策过程，不表示自动获得最优结果。*

我的理解是，规模定律更像预算规划的工具。它帮助回答“下一份资源投到哪里可能更划算”，并没有替我们回答“这个产品是否值得做”。

## 3. 为什么训练最优不等于应用最优

假设模型A训练便宜一些，但每次推理都更耗资源；模型B需要更长训练，却更适合高频服务。只看训练阶段，可能会错过长期运行中的主要成本。

再考虑两个使用场景：每天处理几十次内部查询，与每天处理几百万次请求，成本权重完全不同。延迟要求、批处理机会、用户可接受的失败率，也会改变选择。

我会把一个任务的总账拆成：输入与输出处理、检索及工具调用、重复尝试、验证与人工审核，以及部署维护。API按token收费只是其中一部分。

“单次调用便宜”也不意味着“单个成功任务便宜”。如果它需要不断重试，或产生大量待人工修正的结果，实际成本可能反过来更高。

## 4. 参数量怎样变成内存占用

先做一个最简单的权重估算：参数个数×每参数字节数。70亿参数若每参数使用2字节，单是权重就约140亿字节，约14GB；换算成GiB则约13.0。

这没有包含KV缓存、激活、中间缓冲、运行框架和并行通信等开销。训练还要考虑梯度、优化器状态等内容。因此不能据此承诺“某张显卡一定能运行某个模型”。

量化减少某些数值的存储精度，可能改善资源需求，但需要检查质量和实现。蒸馏则通过训练，让学生模型学习教师提供的信号。两者可以组合，却不是同一种技术。

MoE又增加了一个维度：总参数决定了大量权重的保存需求，激活参数影响每次计算的部分工作量。真实部署还涉及专家分布与通信，不能只用激活参数换算显存。

## 5. 规模外推有价值，也有边界

小实验能够支持预测，但外推依赖假设。如果数据分布变了、训练不稳定、架构发生变化，原来的拟合可能不再可靠。

外推也涉及超参数：小模型上找到的学习率、批大小等配置，不能未经验证直接照搬到大模型。原书讨论的参数化与超参数迁移，正是在尝试让较小实验对大训练更有指导意义；它仍需要对应架构与训练条件。

原书还讨论了能力“涌现”的观察。阅读时我会区分：底层能力是否突然变化，还是评分方式和达标阈值让连续进步看起来像突然跨越。仅凭一张曲线，不足以确定所有机制。

数据和能源等瓶颈也值得关注，但“公开人类文本有限”不等于模型训练将在某一天必然停止。数据质量、重复使用、多模态、合成资料及训练目标都会改变问题；这些方案各自又有新的成本和风险。

## 6. 补充：2026年更值得细读的是计算的组成

DeepSeek在2026年9月的V4.1-Flash发布说明中，分别披露输入侧与输出侧激活参数，并讨论缓存存储的改善。这说明，仅比较一个总参数数字，已经难以描述不同阶段的资源行为。[官方说明](https://www.deepseek.com/en/news/deepseek-v4-1-flash/)

这里不直接据官方宣传推断真实业务收益。我的判断是，比较模型需要把输入长度、输出长度、并发、缓存和硬件同时写进实验记录。

推理阶段增加计算也是另一条路线：同一个问题可以分配更多推理预算、生成多个候选再验证。它与增加模型参数不同，后续采样篇会展开。两者都可能改善某些任务，也都需要用成功率与成本验证。

## 7. 我会怎样比较两个候选模型

| 检查项 | 固定或记录的条件 |
| --- | --- |
| 任务质量 | 相同问题、资料、评分规则与人工复核方式 |
| 响应时间 | 首token、完整响应及慢请求分布 |
| 运行成本 | 实际输入输出、缓存、工具、重试与审核 |
| 部署条件 | 精度、硬件、并发、批大小与服务版本 |
| 失败行为 | 资料缺失、长输入、格式错误和超时 |

如果模型B的平均分更高，但在关键类别里漏掉安全条件，我不会让平均成绩替它过关。如果模型A略慢，却能显著减少返工，它也可能更适合当前任务。

这一节改变了我阅读模型发布信息的顺序：先明确任务和约束，再看数据与结构，最后把规模放回成本账本。**参数是解释模型的线索，完成任务的证据才是选择它的理由。**
