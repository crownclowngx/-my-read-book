# 第八章（3/3）：数据处理——把收集来的样本整理成训练数据

第一篇明确需要什么数据，第二篇讨论怎样扩展和验证。现在假设我们已经得到一批候选样本：公开数据、经过允许使用的业务材料，以及人工或模型生成的问答。它们放进同一个目录，还不能直接说明已经适合训练。

原书8.3依次讨论数据检查、去重、清理与过滤、格式化。这条顺序让我更容易区分几件事：先认识手里的材料，再决定保留什么，最后将它们转换成模型能够正确解释的形式。

## 8.3 数据处理

原书首先提醒，每个处理步骤都可能耗费大量时间。应先在小样本上试运行，检查结果，再应用到全量数据；原始材料也应保留，以便发现脚本错误时恢复和重新处理。

具体步骤的执行次序需要考虑成本。如果去重很快、逐条语义审核很贵，可以先减少重复；如果低质量过滤十分便宜，也可能先过滤。文章的小节顺序帮助理解任务，实际流水线则需要结合数据和资源安排。

### 8.3.1 数据检查

先问数据来自哪里、经过什么处理、是否包含所需上下文。一个“问答对”可能只剩下用户最后一句话，丢失前面的城市与日期；也可能把工具返回内容误放进了助手回答。

接着检查数量和分布：输入输出长度、语言、来源、任务类别、响应行为，以及标注员或生成模型之间的差异。平均长度看似正常，仍可能存在一批被截断的长响应，或者某个来源几乎只包含拒答。

这与第四章的分组评估相连。总体指标可以帮助发现变化，具体分组才能说明问题发生在哪里。对于前文五类问题，应分别查看覆盖和质量，再增加回答、追问、资料不足等行为维度。

原书还强调人工检查。阅读一些完整样本，可以发现统计表没有表达的问题：所谓“正确答案”引用了过期制度，指令与上下文互相矛盾，或者原始材料中根本没有支持结论的依据。

有多个标注时，还要检查分歧。两位标注员的答案不同，可能因为规则含糊，也可能因为一个人遗漏了每晚限额。先解释分歧，再决定修订指南、重新标注还是排除无法判定的样本。

我会保留一份问题记录，写清样本、现象、原因和处理决定。这样，下一次遇到相同模式时，才知道应该修数据、改规则，还是进一步调查。

### 8.3.2 数据去重

重复会改变模型看到的数据分布。原书用多次出现的红色铅笔价格说明：数据里的偶然重复，可能让模型把颜色与高价关联起来。重复跨越训练与测试，还会使评价更容易受到记忆影响。

处理之前，需要先定义重复的单位：整条对话、单个问答、段落，还是文档。相同制度段落出现在多个不同任务的上下文里，未必应该一律删除；相同输入却有冲突答案，则更需要核查标签。

原书介绍成对比较、哈希与降维等方法。完全一致可以用哈希辅助识别；小幅改写可以用近似匹配寻找候选；表达不同但含义接近的内容，还可以借助向量相似度。方法越接近语义判断，越需要关注阈值与误判。

对报销助手，下列两题看起来很像，却可能需要不同答案：

- “普通员工在A市住宿，每晚最多报多少？”
- “普通员工在B市住宿，每晚最多报多少？”

城市、日期、人群或例外条件的一个字变化，都可能改变适用条款。因此，相似度适合帮助发现候选，删除决定仍要结合任务字段与制度依据。

当前NeMo Curator文档区分精确、模糊与语义去重，分别采用哈希、MinHash与LSH、嵌入等技术。这可以作为原书方法的实现参照；选用工具时还应确认版本与资源需求。[官方文档](https://docs.nvidia.com/nemo/curator/latest/curate-text/process-data/deduplication)

去重与数据切分也需要配合。把一条种子问答的原句放进训练集、三个改写放进测试集，即使文件随机分开，也没有实现问题层面的独立。

我会记录原始问题与生成变体所属的问题族，按评估目标进行分组切分。如果要测未见制度上的泛化，还需进一步考虑制度文档之间的隔离；如果任务就是利用固定知识库回答新问题，则应围绕新问题和派生内容设计划分，并说明这个测试实际测量什么。

### 8.3.3 数据清理与过滤

清理首先处理无关格式、损坏文本和不需要的字段。网页导航、重复页脚和异常编码通常会干扰阅读；制度表格中的标题、注释和日期却可能决定答案，不能为缩短文本一起删除。

第五章已经讨论上下文组织。进入数据处理后，同样需要区分外部资料与任务指令。资料中出现“忽略之前要求”这类文字时，它可能是需要识别的干扰内容；是否保留作为安全样本，要看训练目标与标注，不能让它意外成为应用指令。

敏感信息、禁用字段、毒性内容和不符合使用要求的数据需要按政策处理。匿名化或合成并不自动保证材料适用，仍要检查保留下来的细节与用途。

质量过滤还可以复用第二篇的验证方法：检查引用和计算，筛出上下文缺失、答案矛盾、过长或过短的样本，并人工检查误删与漏删。

清理完成后应重新看分布。假设某个过滤器更容易删除中英混合问句，最终数据可能格式更统一，却丢掉原本需要的语言场景。保留数量与删除比例只是线索，还需要检查被删掉的具体内容。

当样本超过预算时，原书介绍主动学习、重要性采样与数据剪裁。它们的目标是把有限资源用于更有价值的数据，但“价值”仍需要任务相关的衡量。只挑最难的问题，未必能代表日常业务。

### 8.3.4 数据格式化

最后需要将保留的数据转换成训练框架和模型要求的形式。第五章的系统提示词、用户提示词与对话模板，到这里成为模型解释样本的重要条件。

下面是一条简化的对话结构示例。假设金额与审批条件均已明确，实际框架的字段要求仍应按文档确认。

```json
{
  "messages": [
    {
      "role": "system",
      "content": "依据提供的制度回答，说明适用条件和出处。"
    },
    {
      "role": "user",
      "content": "制度R-2026第3条：A市住宿每晚最高600元，超出自理。普通员工住两晚，每晚700元，其他条件均满足，可报多少？"
    },
    {
      "role": "assistant",
      "content": "按第3条，两晚最多可报1200元，超出的200元自理。"
    }
  ]
}
```

来源版本、支持片段、标注记录、问题族与切分归属可以保留在数据管理记录中，再由导出步骤选择模型真正需要的字段。它们不必全部进入用户提示词，也不能在转换中悄悄丢失。

格式正确以后，还要抽查模型实际接收到的文本：角色有没有颠倒，特殊token是否匹配，长上下文是否被截断，目标回答是否完整。第七章讨论过的损失掩码，也需要确认是否覆盖了期望学习的部分。

原书以食物分类说明，微调可以使模型使用更简短的任务格式。但训练与推理仍需保持一致。训练时有固定前缀，部署时遗漏前缀；或者训练时提供制度，部署时却不提供，都可能改变任务条件。

## 8.4 小结

第八章依次讨论数据策展、增强与合成、处理。三者会互相反馈：检查时发现某类场景不足，就回去补数据；复核时发现标签不一致，就修订指南；独立评估没有改善，则继续调查数据、训练和任务定义。

第四章帮助定义好结果，第五章帮助表达任务，第六章组织资料与工具，第七章选择适配方式。第八章将这些要求进一步落实为可以检查和维护的训练材料。

对贯穿全系列的知识库助手，我会保存这样一组最小记录：来源与制度版本、原始样本与派生关系、标注与验证依据、处理规则与数据版本，以及使用哪些独立材料判断模型是否改善。

已有30题继续用于开发与回归；进入训练或反复调参的内容，需要重新考虑评估用途。数据更多、文件更整齐、训练损失更低，都需要与实际任务表现一起判断。

我读完这一章最想实践的，是让每条保留或删除决定都有依据，让每次训练能回到具体问题上复核。准备好数据并训练出模型之后，下一章继续讨论如何优化推理，让质量、延迟与成本共同满足应用要求。
